# 我做了哪些功能：从总览到每一个页面

更新：2026-10-11。介绍当前开发版；截图展示拍摄时的界面，源码实现、单次演示和稳定性验收分别说明。

## 1. 功能总览

| 功能组 | 当前能力 | 主要入口与状态 |
| --- | --- | --- |
| 主页与屏保 | 圆形时钟、壁纸 + 数字时间；纯时钟屏保 | 设备主页 / 设置 / 网页；圆形时钟已有实拍 |
| 天气 | 实况、未来 12 小时、US AQI、PM2.5、UV 与高于 3 的时段、风与湿度 | 天气主页和两个二级页，均有实拍 |
| 语音对话 | 本地“小冰小冰”唤醒、长按说话、云端问答、连续接话 | 已有唤醒、查询演示；播报与打断仍需优化 |
| 语音执行 | 时间、天气、音量、主页、任务等受限设备工具 | 时间天气、音量有演示；其他命令按场景回归 |
| 事项 | 闹钟、提醒、待办、备忘录、纪念日/倒数日 | 时钟二级页只放闹钟，其他集中管理；最多 8 条任务、4 项纪念日 |
| 专注 | 倒计时、番茄钟与专注/休息设置 | 桌面工具入口；尚未补齐专项演示 |
| 媒体 | SD 图片、动态壁纸、本地音乐、环境音、循环与定时停止 | 设备菜单与网页；不与语音/提醒混音 |
| 系统设置 | 音量、亮度、方向、姿态校准、唤醒、夜间外观 | 设备设置页；部分适合网页管理 |
| 文字记录 | 有界上下文、长期记忆、历史检索与删除 | microSD 与语音工具；网页查询当前文字卷 |
| 网页管理 | 状态、设置、AI 播报语速/音色、媒体、事项、历史与手动诊断 | 同网浏览器；新布局与接口已通过主机检查和固件编译，语速/音色待烧录听测 |

游戏已备份并从当前固件移除。我现阶段优先做好桌面和语音体验，而不是继续增加菜单数量。

## 2. 主页：抬头就能读到的信息

<p align="center"><img src="images/2026-10-11/device-clock-front.jpg" width="300" alt="圆形时钟主页实拍"></p>

我保留两种主页：圆形时钟，以及壁纸配数字时间。背景素材和主页类型分别保存，所以切回时钟不需要先删掉壁纸。进入屏保后统一显示不带壁纸的时钟，避免把两种状态混在一起。

本次照片展示圆形时钟；动态背景的动作不能由静态照片证明，后续会补录切换与重启保持的过程。

## 3. 闹钟：从主页进入，倾斜调时间

| 小时编辑 | 分钟编辑 |
| --- | --- |
| ![选择闹钟小时](images/2026-10-11/alarm-edit-hour.jpg) | ![选择闹钟分钟](images/2026-10-11/alarm-edit-minute.jpg) |

主页的二级页只保留闹钟。调节小时、分钟时，倾斜幅度越大，数值变化越快；回到中位停止调整。网页适合输入具体日期、名称和重复规则，设备适合随手查看和快速修改。

工作日指周一至周五，不包含法定调休表。界面设置完成并不等于到期播报已验证，后续演示会补齐“设定 → 到期 → 取消 / 重复”的完整过程。

## 4. 天气：概览、小时趋势、参数卡片

| 当前天气 | 未来 12 小时 | 天气参数 |
| --- | --- | --- |
| ![天气概览](images/2026-10-11/weather-current.jpg) | ![小时预报](images/2026-10-11/weather-hourly.jpg) | ![天气参数](images/2026-10-11/weather-metrics.jpg) |

概览负责快速查看天气和温度；小时预报通过倾斜变速滚动看完 12 小时，不把全部时刻挤进一屏；参数页把空气质量、紫外线、风和湿度分别做成组件。UV 模块同时显示当前数值和当天大于 3 的时间段。

这些数值来自网络天气服务，不是板载温湿度或空气质量传感器。US AQI 是使用的评价口径，不能把它与中国 AQI 的同一数字直接等同；照片中的数据只代表拍摄时状态。

## 5. 语音：听见要求，也执行操作

| 聆听 | 处理 | 回答 |
| --- | --- | --- |
| ![聆听状态](images/2026-10-11/voice-listening.jpg) | ![处理状态](images/2026-10-11/voice-processing.jpg) | ![回答状态](images/2026-10-11/voice-speaking.jpg) |

本地模型负责发现唤醒词；识别、大模型和合成语音走云服务。用户明确说出本机快捷命令时可以直接处理，其他请求由模型判断是否需要白名单工具，设备负责校验并执行。模型不能因为“觉得应该成功”就代替设备报告成功。

原有按键仍保留：长按发起语音、播放中按键取消。完整回答后有接话窗口，可以继续说下一句；明确结束对话与按键取消用于退出会话。回答中再次说唤醒词可以请求打断，但回声、漏检和新问题接续仍是正在优化的部分。

这次提供 [查询时间天气、调整音量的完整视频](SHOWCASE.md#6-两段完整视频)。语音页面本身不是音量已变化的证明；回归需要同时查看设置回读与实际声音。

## 6. 桌面工具和设置：入口清楚，操作一致

| 桌面菜单 | 设置菜单 |
| --- | --- |
| ![桌面工具入口](images/2026-10-11/desktop-menu.jpg) | ![系统设置入口](images/2026-10-11/settings-grid.jpg) |

按键负责确认和返回，姿态传感器负责选择、翻页与连续调节。我将专注、媒体、任务等功能集中到各自入口；截图中的历史入口图标不能用来推断已经移除的游戏仍然存在。设置照片中显示的百分比是对应选项的状态，不能当成语音调音量前后的对比图。

## 7. 网页：负责整理，不复制一块小屏幕

新增的管理布局分为概览、外观、媒体、事项、对话和诊断。批量传文件、编辑名称、找历史和导出诊断适合放到大屏；倾斜校准、实体按键和日常语音仍留给设备。

![网页管理概览，模拟数据预览](images/2026-10-11/web-overview-desktop.jpg)

截图是本机浏览器的模拟数据预览，不是已刷入设备的运行证据。接口范围、手机布局和验收步骤见 [网页设计与使用](WEB_MANAGEMENT_DESIGN.md)。

## 8. 还在打磨什么

我已打通主要功能，但不会把“菜单有入口”与“体验已稳定”画等号。目前重点仍是播报连续性、回答中唤醒词打断、打断后的干净采音，以及网络异常后的恢复。新网页和新版结构也分别需要设备回归与打印试装。

下一步的可靠性目标与新能力安排见 [开发计划](ROADMAP.md)。新功能只有完成实现并有对应证据后，才会从计划移入这份能力总览。
