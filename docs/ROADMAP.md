# 我接下来想把 VoxConductor 做成什么样

更新日期：2026-10-11。

我希望它最终是一台可以长期放在桌面上的语音助手：看得清、操作顺手、回答连贯，设置做了就真正生效。当前已经有了实物和基础功能，下一阶段我会优先提高可靠性，再扩展能力。

## 第一优先级：让语音链路稳定

我会固定硬件摆位、音量、固件和测试语句，分别验证空闲唤醒、正常回答、回答中唤醒词打断和连续接话，避免一次修改多个参数后无法判断原因。

- 播报：区分云端音频不足、任务调度延迟、I2S/DMA 供给间隙，结合听测和分层日志验证。
- 打断：确认唤醒词检测、停止旧声音、新问题采集和旧轮清理都各自完成；重点排除把尾音当成新问题。
- 退出：按键取消和明确的“结束对话”命令能回到桌面，不自动重新聆听。
- 资源：控制内部 RAM 峰值和最大连续块，PSRAM 与 SD 各司其职；网络失败要清理资源并可再次使用。

验收不是“出现一次成功日志”，而是同一组场景可重复通过。成功率和延迟指标只在记录了样本数、版本与测量口径后公布。

## 第二优先级：让语音控制可信

我会继续保留模型理解自然语言、设备执行受限工具的分工。时间、天气、音量、主页和任务都必须使用真实返回值，避免模型已经说“改好了”，设备却没有改变。

先完善参数校验、执行后回读、失败提示、跨轮上下文和重启保存，再考虑增加工具。不存在的数据要明确说没有，不能用历史天气充当当前天气。

## 第三优先级：把网页管理做清楚

管理网页已在本机改为概览、外观、媒体、事项、对话和诊断六个区域，加入配置草稿保护、保存前合并最新值、保存后回读、事项筛选与清晰的连接反馈。电脑与手机布局已用模拟数据检查，尚待新固件实机回归。详细范围见 [网页管理](WEB_MANAGEMENT_DESIGN.md)。

下一步先验证设备忙、窗口过期、缺卡和断网时的结果，再完善轻量只读状态、受限传输取消、历史按轮次组织。不会在界面里加入没有后端支持的按钮。

网页仍定位为同网管理，不直接扩展成公网平台，也不引入与设备体量不匹配的账号系统。

## 第四优先级：提高复现与维护质量

- 将当前开发版代码、配置模板、测试入口和文档按一致版本整理发布。
- 已归档 KiCad、制造资料、板载 BOM 和 V3 结构；下一步写回 J2 实物修正、补全采购料号，并完成 V3 入口框/底盖试装。
- 用固定回归清单覆盖语音、闹钟、天气、SD、网页与断网恢复。
- 保留默认简洁日志，深入诊断按需开启，不让调试信息影响正常音频任务。

硬件工程见 [hardware/](../hardware/README.md)。现有 V3 几何检查与交付校验不代替树脂公差、线束和螺纹强度实测。

OTA/恢复入口值得后续设计，但分区空间、模型文件、升级回滚和断电恢复都需要先评估。它目前是计划，不是已完成的升级功能。

## 暂时不做

我暂时不恢复游戏，也不优先加入多用户账号、公网远程控制、社交功能或无限制工具系统。现有板上没有的环境传感器和电池检测，不会只靠页面增加一个数值就宣称支持。

这些取舍不是放弃扩展，而是先把一台桌面设备最常用的事情做好。
