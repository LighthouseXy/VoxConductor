# ESP32-S3 云端直连语音、记忆与工具

更新日期：2026-10-10。以下针对当前开发版，最新固件不包含在本次文档与素材提交中。

当前主流程在 ESP32-S3 运行，不需要电脑 FastAPI。ASR、DeepSeek、TTS 推理仍使用互联网云服务。功能职责、实现状态与实机验证步骤统一见 [语音对话实施方案](VOICE_DIALOGUE_AND_MEMORY_PLAN.md)。

我目前使用“小冰小冰”做本地唤醒，并接入连续接话、唤醒词打断、结束对话、设备工具和 SD 记录。已有查询与音量控制演示；播报连续性和打断边界仍需实机回归。游戏已移除。见 [展示图集](SHOWCASE.md) 与 [开发日志](logs/README.md)。

## 配置与启动

1. 复制 `firmware/main/cloud_credentials.example.h` 为同目录的 `cloud_credentials.h`，填写自己的密钥。已有 `server/.env` 时可使用 `python3 tools/import_cloud_config.py`，脚本不覆盖已有配置，也不打印凭据。
2. 在 `wifi_credentials.h` 配置 2.4 GHz Wi-Fi。默认 ASR/TTS 使用百炼中国内地端点，其他地域必须同步检查端点、模型与密钥。
3. 在 VS Code 中将 ESP-IDF 项目目录设为仓库的 `firmware`，使用 ESP-IDF 6.0.2 构建与烧录。首次会下载 ESP-SR 等依赖。当前 sdkconfig 已启用 小冰小冰 编译开关与 AEC 打断，并选择 partitions_wake.csv；运行唤醒仍需设备设置开启。Kconfig 的唤醒编译默认值与仓库 sdkconfig 的实际选择需区分。
4. 等待 Wi-Fi 与 SNTP 校时成功。HTTPS/WSS 保持证书校验，不通过关闭验证绕过时间问题。

ESP-IDF 终端等价命令：

```bash
cd firmware
idf.py reconfigure
idf.py build
idf.py flash monitor
```

`dependencies.lock` 由组件管理器在重新配置时更新。不要手工猜测新组件的哈希。

当前 ASR 使用 `qwen3-asr-flash-realtime`，配置宏为 `CLOUD_ASR_REALTIME_URL`；旧整段 ASR 函数保留但不是默认入口。已有私有配置未定义新宏时使用中国内地实时端点。LLM 为 `deepseek-flash`；TTS 使用原有实时端点及音色。

密钥头文件被 Git 忽略，但密钥仍在固件中，不可公开 BIN、ELF 或整个 build 目录。新增局域网令牌同样不能公开。SD 文字为明文存储，不自动保存录音。

## 默认交互与语音链路

- 四个基础页使用左右倾斜切换，单击进入/确认、双击返回；时钟单击直接进入闹钟。工具为九宫格，游戏已从当前固件移除。
- 普通长按 500 ms 开始录音与上传，松开发送，保留 1～20 秒范围。处理中单击取消，不切页，不续播旧回答。
- 识别最终文本 → 本地命令或上下文 → DeepSeek/按需工具 → 单会话连续 TTS → I2S 播放。
- 本地 小冰小冰 运行开关开启且模型就绪后，空闲音频只送本机检测；唤醒后等聆听状态再提问。有讲话后静音约 1200 ms 结束，自动录音有八秒无活动和二十秒上限。
- 唤醒对话回答后进入十二秒接话窗口，可直接问下一句，不必再说 小冰小冰；没有接话则安静退出，不把静音发给云端。
- 回答播放中使用 AEC 后的音频检测唤醒词，命中才取消旧回答；普通响声不直接触发。结束命令在 ASR 后本地处理，语音忙时仍可按键取消。

模型从受限白名单中自行选择是否调用工具（tool_choice=auto），设备校验并执行；明确的本机快捷命令可直接处理。当前先完成 LLM 工具和最终文本、释放连接，再建立单会话 TTS 接收和播放 PCM，不再把 LLM 与 TTS 并行作为默认方案。

## 记忆与本地命令

| 说法 | 作用 |
| --- | --- |
| “记住我喜欢喝茶” | 模型准备一条记忆，复述名称和内容，尚未保存 |
| “确认保存” / “取消保存” | 120 秒内确认或取消当前记忆准备 |
| “修改记忆，饮品改成咖啡” | 同名条目更新，仍需确认保存 |
| “查看记忆” | 读取未过期长期条目 |
| “开始新对话” | 清空近期上下文、摘要和活动讨论，保留长期记忆与任务 |
| “删除记忆：饮品” | 准备删除实际名称及命中的关联来源；保留无关原文、长期条目与任务，重新整理摘要/讨论 |
| “清空全部记忆” | 准备清空新格式对话、摘要、长期记忆和任务 |
| “确认清空” | 120 秒内执行明确说明过的删除范围 |
| “重试删除” | 继续之前已确认但未完成的定向删除，不扩大删除范围 |
| “一分钟后提醒我喝水” | 调用本机工具保存单次提醒；无需再次确认，保存成功才报告已设置 |
| “每天上午九点提醒我喝水” / “工作日下午三点提醒我站起来” | 保存钟点循环提醒；工作日为周一至周五，不含法定节假日表 |
| “每周一上午十点提醒我开会” | 每周按相同星期/钟点触发，不累加播报耗时 |
| “修改喝水提醒为下午四点” / “把喝水提醒推迟五分钟” | 先查任务 ID，准备修改；下一轮确认执行才保存；稍后不改变循环锚点 |
| “添加待办：买牛奶” / “完成待办：买牛奶” | 准备创建或完成同名待办 |
| “确认执行” / “取消执行” | 确认或取消任务修改、待办/设备的准备操作；提醒创建不需要此确认 |
| “查看待办” / “查看提醒” | 以可朗读文字列出本机任务，不朗读原始 JSON |
| “添加备忘录：明天带充电器” / “查看备忘录” | 明确新增备忘直接保存原话片段，最多四十个中文字符；不自动播报到期，与待办确认规则不同 |
| “开始专注” / “开始番茄钟” / “暂停专注” / “继续专注” / “停止专注” | ASR 后本地处理，不调用 LLM；时长在设备设置中选择 |

记忆管理命令采用精确匹配，允许末尾句号/感叹号；删除特定条目要求“删除记忆：完整名称”。专注命令目前只匹配表中的固定短语及末尾中文句号，不是任意自然语言计时。ASR 若改写了名称，请先查看记忆，再按返回的名称操作。任务变更采用 ID，动作词与原话不符或是否定请求时不准备执行。

删除清理的是此前的数据；删除成功后的确认提示可能作为一条新的操作记录保存，不含已删除的条目内容。失败或取消的对话会撤销尚未确认的准备项，不撤销已经执行的动作。

最近上下文最多 6 对，长答案只在窗口内保存带标记摘录，完整生成原文分块归档至 SD。每轮按正文预算选择近期材料及最多 6 条相关有效记忆，通用沟通偏好优先；活动讨论保留目标、约束、候选方案、选择和未解决问题，用于有限的短追问衔接，不承担动作授权。

旧轮进入有界摘录和待摘要材料。空闲且资源允许时自动请求滚动摘要并整理讨论状态，输出上限 1400 Token；新结果需要版本及原材料匹配、写入成功才替换。普通问答和摘要均关闭模型思考模式。摘要调用会额外消耗云端 token，日志单独显示。

长期记忆最多 16 条，任务最多 8 条。短期事实按有效期过滤，“今天”不跨北京时间当天；设备未校时不使用有时限的记忆。多人共用时共享一个本地档案，不进行身份识别。

## 本地记录与恢复（M1）

`APP_STORAGE_MEMORY_ENABLED`（`app_storage.h`）默认为 1，控制结构化文字保存与恢复；设为 0 不删除已有文件。关闭持久存储后，需要落盘确认的记忆/任务操作不会报告保存成功。

| SD 文件 | 内容 |
| --- | --- |
| `dialogue.jsonl` | 用户原文、助手原文及成功/失败/取消终态，通过轮次 ID 关联 |
| `dialogue.1.jsonl`～`dialogue.4.jsonl` | 最多四份封存原文卷；不自动覆盖，当前设备检索不搜索这些卷 |
| `context0.json`、`context1.json` | 近期上下文、摘要、待摘要材料、活动讨论、长期记忆和任务的交替快照 |
| `history.idx` | 空闲增量生成的历史定位索引；可重建，不替代原文 |
| `erase.pending` | 删除事务未完成标记；存在时不恢复或检索旧数据 |
| `dialogue.rewrite` | 定向删除期间的临时原文文件，完整写入后才替换日志 |
| `conversations.txt` | 旧格式记录保留，不自动导入或删除 |

快照末尾附换行、8 位校验值、换行，并非纯 JSON 文件。写入检查 flush、sync、close 和读回校验；较新槽损坏时读取另一个有效槽。双槽不能保证 SD 硬件或文件系统整体损坏时恢复全部数据。

任务状态也在快照内；损坏后回退旧槽可能丢失最后一次状态变更，因此不宣称跨介质故障的 exactly-once 提醒。正常复位不重放已提交的提醒或设备命令。

当前卷上限 8 MiB；在新轮开始时剩余不足 128 KiB 则尝试封存到空槽，最多四卷，索引只为新当前卷重建。封存槽满或失败停止该轮日志追加并提示，快照仍独立更新。快照单文件上限 160 KiB。日志与快照不是跨文件事务，断电可能丢失最近提交。长文本按完整 UTF-8 字符分块，并保留原文偏移与总长度；播放失败/取消的上下文明确标记未完整播放，不把已发送至 TTS 的回答当成已播报。

导出：设备断电后将日志复制到电脑，再运行：

```bash
python3 tools/export_dialogue.py /path/to/dialogue.jsonl
python3 tools/export_dialogue.py /path/to/dialogue.jsonl --turn 轮次ID --json
python3 tools/export_dialogue.py /path/to/copied-sd-directory --json
```

脚本不修改原文件、不联网，跳过空行和无效半条 JSON。目录导出读取四份封存卷及当前卷，封存槽编号不作为永久时间顺序，时间以记录中的 UTC 为准。当前网页支持媒体文件传输及当前卷有限对话查询，不提供任意 SD 文件浏览或整卡下载。

电脑备份示例（将路径换为自己的离线 SD 挂载点和一个不存在的新目录）：

```bash
python3 tools/backup_sd.py /Volumes/VOX_SD /path/to/new-backup-directory
```

默认只复制受管文件并核对 SHA-256、写入 `manifest.json`，不删除原卡文件。需要释放封存槽时，使用另一个新备份目录并显式加 `--retire-archives`；脚本先核对文件、刷新备份文件及目录，再删除原卡封存卷并刷新原卡目录，不删除当前卷/快照/无关文件。删除屏障存在时拒绝清理。设备必须断电，不能带电拔卡或与电脑同时写卡。备份包含明文私密对话，设备上的记忆删除不会自动清理这些电脑副本。

## 时间、天气、历史与设备工具

工具由模型按需调用，最多两次工具往返、四次调用。查询当前时间明确 UTC+8；天气复用缓存，包含城市、来源、观测时间、缓存年龄。默认杭州，支持当前天气、紫外线、空气质量、风和未来十二小时预报，不支持任意城市。

天气位置在 app_weather.h，默认杭州坐标。get_weather 的 detail 可选择 current、uv、air、wind、hourly；UI 与工具复用后台缓存及有效性信息。空气质量保持 USAQI/PM2.5，不混称中国 AQI；成功数据保留更新时间，无缓存不填零。

历史工具支持关键词、UTC 区间、角色和轮次筛选，每次最多三条 768 字节命中片段。索引检查最多 2048 项、读取约 512 KiB 原文；索引未完成时使用约 512 KiB 原文窗口。结果携带 `record_id`、`more` 与继续查询游标；可按 ID 读取原文块，长答案块具有整轮原文长度/块偏移。同参重复查询被拦截，改参数重查仍受每轮工具预算约束。只搜索当前卷，结果明确给出未搜索的封存卷数量；没有找到不代表所有历史不存在。定向删除和全量清空包含受管封存卷，但不清理电脑副本和旧格式文本。

本机提醒使用已保存的到期时间，不让模型自行生成成功状态；到期不调用 LLM，无前置提示音。联网时直接 TTS 播报具体事项，断网、云端未配置或失败时播放固件内置“时间到了，请查看屏幕上的提醒。”，屏幕保留具体标题。本地音源为 24 kHz/16 位单声道约 3.44 秒，支持按键取消，不承诺本地音源的 AEC 声学打断。任务与快照初始化不依赖云端密钥，但绝对钟点仍需有效时钟。循环周期提交状态和下次到期先保存，不因正常重启重播旧周期。完整规则见实施方案 M7。

云端短提醒尽量完整接收后起播，长提醒接近缓冲上限时开始消费，播报期间提高优先级；本地音源分块送 I2S 并等待 DMA 尾部清空。显示字体已覆盖新增菜单及固定提醒文案，连续性与屏幕效果待实机回归。输出音量默认 35%，可从桌面工具设置页按 5% 步进调整并保存 NVS。

局域网配置和独立 ESP32 示例见 [局域网设备接入](LAN_DEVICE_PROTOCOL.md)。写操作必须经过下一轮“确认执行”，超时后只报告结果未知，不自动重试。

## 轮次日志（M0）

VS Code 的 ESP-IDF 监视器即可查看，无需电脑服务。可过滤：

```bash
idf.py -p /dev/cu.usbmodem142201 monitor --no-reset --print-filter "voice:I app_cloud:I app_cloud_tts:I app_storage:I acoustic:I voxconductor:I *:E"
```

端口替换为实际端口，先关闭其他串口监视器。串口不会自动归档为电脑文件，需要自行启用监视器日志保存。

- 用户/助手文本：生成原文，不代表成功播放。`APP_TURN_LOG_TEXT=0` 可关闭正文打印，不影响 SD 开关。
- 识别全程：包含录音、连接和识别；“松开后识别等待”单独表示录音结束至最终文本。
- 回答流水线：包含按需工具循环及等待播放完成，不能与纯模型耗时直接比较。另记录“最终文本接收完成”（含工具但不含等待播完）、模型请求/工具调用/TTS 会话数与文本追加段数。
- 缓冲等待：起播后 PCM 耗尽的等待次数和累计时长，不含首次预缓冲；不能单独判断硬件声学是否连续。提醒另列完整接收标志、起播缓冲和任务优先级。
- 首文本：生成开始至收到第一段内容；工具参数不是正文首文本。
- TTS 首 PCM：首句 TTS 开始至音频到达；首次 I2S 提交不是实际声学首声。
- PCM 已提交：成功交给播放函数的原始单声道 PCM 字节数；不证明用户听清。
- tokens：响应 usage 的输入/输出/合计，缺失显示未知；摘要调用单列。
- 资源：阶段内部堆、最大连续块、PSRAM、当前任务栈余量；历史最低值从启动累计。

## 声学模块与资源限制

当前使用 AEC 后的 WakeNet 唤醒词检测进行回答中打断，不再用普通 VAD 响声直接取消。扬声器 24 kHz，音量处理后的参考转换到 16 kHz；旧播报尾音保护、新人声确认和清理顺序见 [语音实施 M6](VOICE_DIALOGUE_AND_MEMORY_PLAN.md#m6唤醒连续接话打断与退出)。

### 本地唤醒

1. 核对 `CONFIG_VOX_WAKE_WORD=y`、`CONFIG_VOX_WAKE_MODEL_NAME="wn9_xiaobinxiaobin_tts"` 与 ESP-SR 模型选择。
2. 使用匹配的 partitions_wake.csv 和模型分区，核对主控实际 Flash/PSRAM；完整烧录不能只换应用。
3. 在设备设置开启唤醒。界面开关、模型就绪和实际命中是不同状态。
4. 说“小冰小冰”，等聆听再问；回答后十二秒内可直接接话。
5. 本地检测输入为 16 kHz 单声道，十六帧有界队列在 PSRAM，去直流、1 倍增益，请求阈值 60%，实际库日志约 59.5%。这个阈值不是声压分贝值。
6. 回答中说唤醒词可请求打断；只说唤醒词后保持安静，不应把旧声音作为新问题。按键取消始终保留。

定制“小助小助”目前只有申请记录，没有已交付模型依据；只改显示文字不会改变实际识别词。

### 结束对话

聆听时可说“结束对话”“结束语音对话”“退出语音”“退出对话”“不聊了”“先不聊了”“退下吧”。仅完整命令或限定礼貌修饰生效，否定句和普通讨论不能误匹配。结束不清空历史，也不关闭下次唤醒；播放中先唤醒打断再说，或直接用按键取消。

### 内存和播放

TTS 使用 384 KiB PSRAM 队列，普通起播预缓冲 24 KiB；与 I2S DMA 是不同层次。最新扬声器 DMA 为 8×256 帧，在 24 kHz 下约 85.3 ms，写入块同步调整，回声参考补偿排队时间。需要听测验证，不能把缓冲容量当成固定新增首声延迟。

ASR 使用有界录音缓冲并在识别完成后释放；大型文本、快照和音频优先使用 PSRAM。任务栈、驱动控制结构和部分网络/DMA 仍需要内部 RAM，SD 不作交换内存。LLM 与 TTS 连接错开，避免为追求并行把内部堆耗尽。
