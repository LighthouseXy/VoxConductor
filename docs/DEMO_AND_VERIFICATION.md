# VoxConductor V1 验收与验证

最后更新：2026-08-27

## 1. 验收目标

一次完整验收应证明以下链路能够在同一套硬件上连续完成：

```text
启动 → Wi-Fi → 校时/天气 → 按键录音 → ASR → 上下文问答
     → 实时 TTS → 扬声器播放 → microSD 文本记录
```

## 2. 验收前准备

1. 电脑和 ESP32 连接同一个 2.4 GHz 局域网。
2. `server/.env` 已配置百炼、DeepSeek 和天气参数。
3. 固件中的 Wi-Fi 与三个本地服务 URL 指向当前电脑。
4. microSD 已格式化为 FAT32 并插入模块。
5. 扬声器只连接 MAX98357A 的差分输出端，任何一端都不接 GND。
6. 先启动 FastAPI，再给设备上电。

## 3. 端到端验收流程

### A. 信息页面

- 展示主页中的当前时间、Wi-Fi 图标、天气和温度。
- 短按切换到天气页，说明天气来自 Open-Meteo，不是板载传感器。
- 再次短按进入语音页。

通过标准：页面切换完成，时间持续更新，天气页显示城市、温度、天气、体感温度和更新时间。

### B. 单轮语音

- 长按按键约 0.5 秒，看到“聆听中”后说：“请用一句话介绍这个项目。”
- 松开按键，依次观察“思考中”和“回答中”。
- 等待扬声器播放完成。

通过标准：服务端返回 HTTP 200；串口记录相同 `turn_id`；扬声器播放可理解的回答；UI 自动返回原页面。

### C. 上下文

- 测试前执行 `POST /conversation/reset`，确保结果不受旧会话影响。
- 第一轮告知项目代号和主控，例如：“我的演示项目代号是一二三四，主控是 ESP32-S3。”
- 第二轮追问：“我的这个项目使用的主控是什么？”
- 第三轮修改信息：“现在将项目代号改为四三二一。”
- 第四轮追问：“我现在的项目代号跟主控分别是什么？”

通过标准：第二轮能回答第一轮给出的主控；第四轮能使用第三轮更新后的项目代号，同时保留第一轮给出的主控。服务端显示的历史轮次应依次增长，`/conversation/history` 可看到同一 `session_id` 下的消息。

### D. 本地记录

- 完成一轮对话后检查串口是否出现写入 `/sdcard/conversations.txt` 的成功日志。
- 如需展示文件内容，在断电后取卡读取；当前固件没有通过 USB 或 Wi-Fi 暴露 SD 卡文件。

通过标准：文件追加时间、`USER` 与 `AI` 三部分，旧记录不被覆盖。

## 4. 服务端检查命令

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/weather/current
curl http://127.0.0.1:8000/conversation/history
```

清空当前固定会话：

```bash
curl -X POST http://127.0.0.1:8000/conversation/reset
```

## 5. 已有验证证据

- ST7789 和 LVGL 页面已在实机显示，见 `docs/images/`。
- 短按切页、长按录音和松开发送已在实机操作。
- INMP441 音量随声音变化，录音可被千问 ASR 识别。
- DeepSeek 回答通过实时 TTS 以 PCM 流下发，并由 MAX98357A 播放。
- SQLite 能保存上下文，后续轮次能读取最近消息。
- 四轮上下文测试已完成“建立信息、追问、修正、再次回忆”，见 [前两轮](images/context-dialog-turns-1-2.png) 和 [后两轮](images/context-dialog-turns-3-4.png)。
- microSD 能挂载、读写并追加文本会话。
- Open-Meteo 天气已经通过服务端转发到设备页面。

本仓库没有保存正式性能测试数据，因此不对平均延迟、P95 延迟、识别准确率、连续运行时长或弱网恢复率给出未经测量的数字。

## 6. 工程状态与能力边界

| 项目 | 当前实现 |
| --- | --- |
| 模型运行位置 | ESP32-S3 负责设备交互和音频 I/O；ASR、DeepSeek 与 TTS 由 FastAPI 调用云端服务 |
| 上行语音 | 松开按键后上传完整录音，再执行非流式 ASR |
| 文本生成 | DeepSeek 返回完整文本后，服务端才启动 TTS |
| 下行语音 | TTS 音频以 HTTP 分块流传输并在设备端边接收边播放 |
| 对话上下文 | SQLite 保存固定 `session_id` 的最近六轮消息；尚未支持多用户或多设备隔离 |
| 轮次一致性 | `turn_id` 用于校验当前响应，降低迟到响应被错误播放的风险 |
| 本地归档 | microSD 保存用户文本与 AI 回答，不承担在线上下文检索 |
| 产品化状态 | V1 功能原型；尚未完成定制 PCB、外壳、认证和量产验证 |
