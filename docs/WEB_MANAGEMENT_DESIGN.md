# 设备管理网页改进设计

更新日期：2026-10-10。依据 media_web.html、app_media_web.c、app_control.c 与当前设备模块；本文区分已有功能和新增方案。本次只整理设计，不修改网页/固件代码。

我希望网页从“功能集中在一页”变成更清楚的设备控制台。下文导航、视觉和交互改版仍是计划；已实现的无配对码入口和声学诊断单独列在现状中。

## 定位

网页应成为“查看设备状态、调整外观、管理媒体、管理事项和查看对话”的局域网控制台。继续由 ESP32 提供静态 HTML/CSS/JavaScript，浏览器承担图片/音频转换，不新增 React、云账号或另一套任务数据库。

二维码是已联网后的管理入口，不是首次 Wi-Fi 配网。当前设备需要用户在本机开启管理窗口、手机/电脑处于可访问设备的网络，HTTP 不用于公网或不可信共享网络。

## 当前有什么，缺在哪里

| 领域 | 当前已经存在 | 当前缺口 |
| --- | --- | --- |
| 连接 | QR/IP 入口，无需配对码，设备侧开启、十分钟空闲续期 | 缺明确的离线/过期/设备忙区别、手动重新连接流程 |
| 设备 | 联网/校时、运行时间、内部空闲堆、SD、主页/壁纸/音量/亮度/唤醒 | 缺固件版本、RSSI、PSRAM/最低堆/最大块、模型实际就绪与失败原因 |
| 外观 | 圆形时钟或壁纸+数字、静态/四种动态壁纸、夜间亮度和屏保时间 | 缺组合预览、当前应用与编辑草稿区分；屏保应固定无壁纸圆形时钟 |
| 媒体 | 上传、覆盖/删除、播放控制、循环/定时、原图转换与音频转 WAV | 缺清晰进度、取消、失败重试与输出质量解释；图片预览未一致应用压黑 |
| 事项 | 闹钟/待办/备忘录、八条共享记录、编辑/完成/取消/删除 | 缺分类视图、北京时间/下次时间/上次结果呈现；重复标题需显示稳定 ID |
| 声学诊断 | 已有唤醒/打断诊断采集及分轨音频下载，不要求配对码 | 需要引导测试步骤、明确各轨含义和有界采集状态 |
| 语音记录 | 当前卷关键字、三条分页、按记录读取原文块 | 缺按轮次展示、失败/打断状态、当前搜索范围说明和受限导出 |
| 操作结果 | 新设备控制有 job 查询；旧媒体命令部分只返回“已提交” | 保存、持久化与显示应用结果不够一致；自动刷新还可能覆盖用户编辑 |

目前是暗绿风长页面，各功能卡片同时堆放，页面级 busy 标记使无关操作也被锁住。catalog 刷新会重建文件/预览并回填设置，用户正在编辑的内容可能被刷新覆盖。preset pack 的“跳过已传文件”仅在当前页面内存中记录，不是刷新后或断网后的断点续传。

还有两类需要后端配合的限制：

- state 与写操作共用单个作业槽，并由语音互斥的协调路径服务。语音忙时只读状态也可能等待；不能只靠改按钮文字解决。
- 文件上传/下载直接在 HTTP 处理函数中循环传输。结合 ESP-IDF 的 server-task 模型，可以推断长传输会妨碍其他请求及时响应；需要实测确认阻塞程度。异步处理有官方接口，但必须在完成与所有错误路径归还请求，不能无限增加任务。[ESP-IDF HTTP Server](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32s3/api-reference/protocols/esp_http_server.html)

## 导航与外观

采用五个主区：概览、外观、媒体、事项、对话与诊断。电脑左侧栏，手机底部导航；每次只加载当前区需要的数据，管理入口和连接状态固定在顶部。

```text
电脑
┌──────────┬──────────────────────────────────┐
│ Vox      │ 设备名   已连接/设备忙/离线       │
│ 概览     │ 主要内容，最多两列卡片            │
│ 外观     │                                  │
│ 媒体     │ 区域内错误与操作反馈              │
│ 事项     │                                  │
│ 对话诊断 │ 已应用值 / 未保存修改 / 保存按钮  │
└──────────┴──────────────────────────────────┘

手机：顶部连接条 → 单列内容 → 底部五区导航
```

网页不必和设备一样使用完全透黑文字。推荐浅米灰默认、深色可选，暖杏色主按钮，薄边框与少量柔和圆角；黑底只用于 240×240 设备预览。成功/等待/失败同时用图标和文字，不只用颜色。正文至少 14～16 px，触控目标建议约 44 px，保留键盘焦点与表单 label，防止手机横向溢出。

图形风格沿用设备暖色像素图案，但管理页面的信息要清楚、易读。不要全屏透明玻璃、炫光背景或把每个设置都做成九宫格。

## P0：先解决可用性与保存结果

### 连接与概览

顶部显示：已连接、正在连接、设备忙、连接中断、管理已关闭/会话过期。失败提示给可执行下一步：同网、重新打开设备管理、重新扫码，而不是统一“请求失败”。

概览卡片包括：当前时间与校时状态、主页组合、播放状态、下一提醒、SD 剩余空间、语音唤醒的“已开启/模型未就绪”。固件版本与能力位需要新增只读字段；云端密钥只能显示“是否配置”，绝不返回内容。

可见且空闲时每五秒读取轻量状态；切后台停止，失败退避。长上传时减少轮询，保留显式刷新。不要用无限心跳让十分钟无操作超时永远失效：后台诊断读取不应续期，用户实际操作与传输才续期；这需要改现有授权续期规则。

### 配置生命周期

- 页内保留已应用快照与草稿，脏字段不被状态刷新回填。
- 保存状态分为待提交、等待设备空闲、正在应用、已应用且持久保存、暂时生效但保存失败、未应用。
- 发起 job 后串行查询，超时显示“结果未知，请回读”，不能自动重复写入。
- 保存后读回实际值；旧媒体/外观命令逐步采用相同语义，不再把 accepted 当作完整成功。
- 用户离开有未保存内容的页时提示保留草稿或放弃，不重新保存到另一台设备。
- 当前 config 接口要求完整五项，首版合并最新读回值后提交，避免旧草稿覆盖其他设置；后续可增加受限字段更新与版本检查。

验收：编辑中刷新不丢值；SD/NVS 保存失败与 UI 忙能明确区分；设备重启后核对持久设置；网络中断不重复建任务。

## P1：外观与媒体

### 外观区

左右（手机上下）展示设备预览与表单：

- 主页类型：圆形时钟 / 壁纸加数字时间。
- 壁纸来源：静态缩略图，星空/轨道/水母/花园四个动态入口；当前选中项独立标记。
- 数字时间位置、文字颜色/对比度若新增，限制到经过 240×240 验证的少量预设，不开放任意布局编辑器。
- 屏保只提供启用等待时间和夜间亮度，预览固定无壁纸圆形时钟，不继承主页壁纸。
- 图片裁剪、纯黑阈值与亮部增强的最终预览；显示黑色像素占比作为辅助，不虚构真实亮度或全息效果。
- 动态预览先用浏览器轻量示意，标注“浏览器预览，棱镜效果以实物为准”；不新增设备截屏接口作为前提。

首要修正：压黑必须同时作用于预览与导出 RGB565，避免预览好看、设备仍发光。阈值可提供三个有限预设，不把暗图全部拉亮。

### 媒体区

内部三标签：音乐、环境音、壁纸。列表显示名称、类型、字节数、选中/播放状态；音频补充时长/格式来自有界头部解析，不每次读整曲。

上传面板按“选择 → 转换 → 等待上传 → 传输 → 格式校验/落盘 → 完成”显示状态。输出预计大小、当前进度、速率和估计剩余时间；ETA 标记为估计，传输 100% 不是设备保存成功。

浏览器可用原生 XMLHttpRequest 的 upload progress 观察传输字节，无需引入上传库；设备返回确认后才标完成。[MDN 上传进度](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload)

- 每次只转换/上传一个文件，待传列表保留 File 引用，不并行展开多个大 PCM。
- 用户取消传输，设备清理 part 并保留旧文件；失败提供重试。首版从文件头重传，不伪称断点续传。
- 同名覆盖显示旧/新大小与剩余空间，取消默认安全；删除文件需确认、当前播放先停。
- 当前最大输出 WAV 32 MiB，约十一分半；输入大小不是转换后大小。提前估算并拒绝超限，处理浏览器内存/解码不兼容。
- 音质选项只能显示实际支持的 24 kHz 单声道；不放无效的“无损/48 kHz/FLAC直传”开关。
- 批量资源安装显示逐文件完成/失败，刷新后恢复需要设备文件校验或持久队列，不能只靠文件名存在就当相同。
- 下载/浏览器试听目前读取整文件；优先对长音频增加受限 Range 请求，再做流式预览。手机不自动预加载全曲。
- 环境音沿用 env_ 分类约定，同时显示友好名称；不修改原 SD 目录任意路径。

后端首版只增加一个有界传输工作槽，让轻量状态请求可以响应；保持同一 SD 写操作串行，不开启“多文件同时上传”。异常路径必须归还异步请求、关闭文件并恢复资源协调；先有压力实测再扩大并发。

## P1：事项与对话

### 事项区

顶部“闹钟 / 待办 / 备忘录”筛选，共享八条上限与剩余名额。闹钟列表显示北京时间、循环、下次到期、状态、上次播报结果；不要把“已提交播报”显示成“用户已经喝水”。

新增统一编辑面板和常用时间按钮，手动网页保存为明确授权；本地语音记忆/设备操作原有确认规则不因此取消。标题重复时显示短 ID，写动作始终用稳定 ID。

现有完成/重开/取消/删除复用原接口；“稍后五分钟”需要补网页受限动作，沿用任务锚点，不新建重复闹钟。时钟无效时禁止承诺绝对到期，保留草稿。删除和结束循环都需明确范围。

### 对话与诊断区

对话按 turn 分组：用户问题、生成答案、成功/失败/取消/语音打断。长答案按块按需展开，区分生成原文与完整播报。保持每次三条、有界扫描；显示“当前卷，未搜索 N 个封存卷”。

可新增时间/角色筛选和受限脱敏导出，复用现有历史结构；不要直接暴露整个 SD 文件系统。封存卷批量备份首版仍通过电脑离线工具，跨卷网页搜索单独评估。

诊断先提供有限状态：固件/启动版本、运行时间、Wi-Fi RSSI、校时/天气/AQ 更新时间、最近网络错误、内部空闲/最低堆/最大块、PSRAM、SD 错误、模型就绪、最近轮次阶段与缓冲等待。前端显示解释和复制脱敏报告按钮，默认状态不输出 API Key 或无限串口流；原始诊断音频仅在明确启动诊断后提供下载。

## P2 与暂缓功能

| 候选 | 建议 |
| --- | --- |
| 受限设置导入/导出 | 可做；版本化 JSON、字段白名单、大小上限与预览，默认不包含私人任务/对话 |
| 家庭共享、多设备发现 | 先单设备 mDNS/昵称候选；局域网解析不保证所有网络有效，保留 IP 入口 |
| 首次 Wi-Fi 配网 | 单独的 AP/配网页、凭据持久化和失败恢复项目，当前网页不能在未联网时凭空访问 |
| OTA | 当前非双 OTA 分区且固件含用户凭据；需分区/回滚/签名与凭据管理设计，不作为外观改版顺便加 |
| 公网远程控制、账户与多用户 | 当前无配对码的同网 HTTP 管理不适合；需要额外安全与服务范围，暂缓 |
| 网页小游戏操控、社交排行榜 | 不改善核心管理，暂不加入 |
| 设备屏幕实时投送、常驻录音保存 | 暂不加入；已有按需诊断采集，不等于后台持续录音 |

## 推进与验收

1. P0 导航、草稿保护、结果回读、连接/会话状态；先复用现有接口。
2. P1 媒体分阶段进度/取消、准确预览、单传输工作槽与只读状态快照。
3. P1 事项分类、对话轮次、有限诊断；新增字段必须来自真实设备状态。
4. P2 受限导出、配置备份、Range 试听和设备昵称；先通过兼容性/资源检查再扩范围。

验收覆盖手机与电脑浏览器、不同网络/管理窗口过期、语音忙时保存、上传失败/取消/覆盖、接近空间下限、重启回读、缺卡、长答案及私人数据脱敏。持续记录 HTTP 栈、内部最低堆、PSRAM 与语音卡顿，不能为网页进度抢占音频路径。

交付应同时给出页面截图、真实端点/字段、旧接口兼容策略和已执行检查；未完成的后端功能用不可用状态，不放看起来可点却无效的控件。
