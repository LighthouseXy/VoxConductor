## 问题与解决

| 现象 | 定位 | 处理 |
| --- | --- | --- |
| 完全无背光、反复重启 | app_display_init 返回 ESP_ERR_NO_MEM；单个 LVGL 内存池大小超出配置能力 | 先分池，再将基础池/大显示内存正确放入 PSRAM，失败清理，增加内存诊断 |
| 屏幕恢复，天气/维护/提醒任务创建失败 | 显示、TLS 和任务栈仍竞争内部 RAM | 收紧内部常驻占用、调整启动/任务资源；SD 不能替代实时 RAM |
| 天气页“界面忙”、倾斜丢动作 | 动作等待 LVGL 锁超时，更新中存在不必要长锁占用 | 减少重复绘制，输入在 UI 线程递交，连续滚动不在 IMU 任务里占显示锁 |
| UV/PM2.5/阵风显示字母 f | 当前 libc 格式输出未提供预期浮点显示 | 用定点/整数格式输出具体值，不把它误判为天气接口没数据 |
| Computer 开启后崩溃 | WakeNet 清理/重置路径进入无效内部状态 | 生命周期由模型拥有者处理，避免不安全 clean；队列扩到十六帧 PSRAM |
| 模型误显示“未加载” | 阈值请求 0.55 被库量化为约 0.546，精确相等检查误判 | 接受合理量化差异，输入增加 DC 去除、增益和削波统计 |
| 唤醒后问完请求失败 | 自动结束与 ASR 最终提交时序不完整 | VAD 静音约 1200 ms，提交再结束；无活动/最长时限受约束 |
| 空气质量 HTTP=0 / TLS 超时 | 连接失败而非 USAQI 格式不适用于杭州；诊断发现 DNS 路由问题 | IPv4/TLS 诊断、成功数据缓存与重试、优先 DNS；不关闭证书验证 |
| idf.py command not found | 普通终端没有加载 ESP-IDF 环境 | 使用扩展的 ESP-IDF 终端或加载 export.sh，再选择实际串口 |
| 2048 数字格式截断编译错误 | 缓冲只有八字节，不足容纳 uint32 最大十位数字与结尾 | 缓冲扩为十一字节并用 sizeof；不关闭 Werror |
