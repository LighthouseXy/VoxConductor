## 历史方案（2026-10-03）

以下内容整理于 2026-10-03，保留当时的建议、游戏范围与验收口径。内容中的“当前/本轮”指该日版本，不是最新开发版；当日游戏计划已被后续取舍替代。

本文维护当前架构下的优化取舍和实施范围。已接入语音/任务功能见 [语音对话实施方案](VOICE_DIALOGUE_AND_MEMORY_PLAN.md)，本地界面与游戏见 [桌面工具与游戏](DESKTOP_TOOLS_AND_GAMES.md)，连接及存储格式见 [设备直连说明](DEVICE_CLOUD_VOICE.md)。用户已明确游戏是必需功能、可行计划全部实施：2026-10-03 已接入本节列出的九款可行游戏及设备侧桌面功能；代码接入不等于实机验收通过。涉及新增硬件、外部账号或桌面服务的候选仍保留各自依赖，不擅自接入。

## 1. 当前基线与取舍原则

- **当前架构**：ESP32-S3 直接调用云端实时 ASR、DeepSeek 和实时 TTS；设备管理轮次、上下文、工具与 SD 持久记录，不要求电脑 FastAPI 常驻。云端推理仍需互联网，不是离线大模型。
- **不再作为新功能规划**：流式输入/输出、轮次日志、按键取消、JSONL 与快照恢复、滚动摘要、长期记忆、活动讨论、有限工具循环、索引历史检索和定向删除均已接入。
- **本轮新增并已接入**：首页下一事项、天气过期显示、任务图形管理/语音修改、每天/工作日/每周循环、固定离线提醒语音、专注计时、音量设置、九款小游戏、四卷封存与核对后备份。
- **仍需验收**：连续 TTS、Agent/记忆与提醒连续性修复，以及本轮全部新功能；按用户安排未编译或烧录，不能因已有基础语音反馈就认定全部通过。
- **实验能力**：AEC/VAD 与本地 WakeNet 唤醒均已有代码但默认关闭，唤醒需额外选择模型分区；局域网控制已有白名单和第二设备示例，需配置与实机联调。不是已验证的通用全双工或外设平台。
- **仍未接入的候选**：多用户身份、语义检索、无线/桌面同步、账号日历、新增室内传感器和像素宠物素材。它们需明确身份/数据源、服务权限、硬件或视觉资源，不进入当前默认固件。

优先让已有能力稳定、可见、可管理，再扩大范围。不能把“增加 Agent 框架”“更换模型”当成语音流畅、记忆准确或动作可靠的直接替代品。

## 2. 语音、记忆与 Agent：仍值得保留的优化

### 2.1 语音连续性与可观测性

当前已经有轮次和阶段日志，下一步应利用它们建立新链路基线，不再重复开发旧服务器计时方案，也不沿用固定录音时代的耗时作为当前性能结论。

- 连续测试短问答、长回答、工具请求、提醒与取消，统计中位数及 P90；分开记录录音结束到首 PCM、首次 I2S 提交、整轮完成和句间停顿。
- 日志中的 I2S 提交不等于扬声器实际出声；声音是否连贯需要听测或录音佐证。
- 区分普通回答、工具阶段、后台摘要与提醒的资源消耗；观察内部堆、最大连续块、栈余量、缓冲等待及连接清理。
- 若仍有问题，按日志定位分句策略、预缓冲、网络等待或任务调度，再调整；不在没有测量的情况下同时更换 ASR、LLM、TTS。

### 2.2 记忆与历史：从“有模块”转向“回答正确”

已有最近轮次、摘要、长期条目、讨论状态和关键词历史检索。下一步收益主要来自质量验证与针对性修正，不是再加一套同名记忆层。

| 需要验证的问题 | 建议优化方向 | 何时扩大方案 |
| --- | --- | --- |
| “第二个方案”“继续讲”是否承接正确 | 回放短追问、话题切换、编号选择和用户纠正，检查讨论状态是否误注入 | 先证明现有规则在哪些真实说法上失败 |
| 是否记住助手以前的建议 | 用原文检索返回来源与范围，区分完整答案、摘录和未完整播放 | 超出现有窗口且频繁漏检时，再评估更强检索 |
| 用户修改偏好后是否仍引用旧值 | 验证版本、有效期、确认保存、摘要更新和当前纠正优先级 | 不用增加记忆数量掩盖冲突处理问题 |
| 删除后旧内容是否通过摘要/索引重新出现 | 验证关联清理、失败恢复、旧导出副本边界 | 扩展同步前必须设计删除传播 |
| “没有找到”是否被说成“从未说过” | 保留检索范围、分页与截断语义，不把有限搜索当全历史证明 | 需要大规模历史时再迁移重检索任务 |
| 多人共用是否混淆偏好 | 明确当前共享一个本地档案，提供清楚的使用边界 | 只有确有多人需求时新增身份/档案切换 |

建议保留一组固定对话回归题，覆盖追问、纠正、过期、删除、跨重启恢复、未找到和错误工具选择。衡量回答正确率、误检/漏检、错误写操作、首声延迟和 token 消耗，而不是只展示“能记住一句偏好”。

向量检索/RAG 是后续候选，不是必选升级：当前关键词检索无法满足真实问题时，再用同一批问题比较关键词改进与桌面侧语义检索；同时评估来源引用、删除一致性、额外延迟和隐私。SD 容量增加不等于 MCU 可以无界检索。

### 2.3 工具调用与执行可靠性

保留现有窄工具、调用预算、确认与实际执行结果语义。普通闲聊不应为了“像 Agent”强制走多步流程。

- 先测试工具路由是否漏掉常见说法，或把知识问答误判成历史/设备请求；据真实失败样本修正。
- 写操作要校验参数、目标、权限与持久化结果；超时区分失败与结果未知，不自动重复执行。
- 提醒已有自身保存规则，待办/记忆/设备操作各有确认要求；不能为了统一界面而无意取消确认。
- 取消只终止尚在进行的流程，不能声称撤销已执行的设备动作。
- 工具结果、网页与历史原文均作为数据，不作为新的系统指令；不开放任意 Shell、URL 或 SD 路径。

目前没有必要为现有有限工具循环迁移到通用 Harness、多 Agent 或 MCP。只有明确需要接入外部工具生态、复杂长任务或桌面重计算时，才单独评估外部编排；新框架不能替代音频、资源管理和设备权限设计。

### 2.4 声学打断与免按键交互

AEC/VAD 不是新建任务，而是默认关闭的实验模块待验收。当前实现已有 24 kHz TTS 到 16 kHz 的转换及播放参考链路；不再保留“尚需选择是否重采样”的旧二选一计划。

值得保留的工作是校准参考延迟、音量、箱体/麦克风位置和静音尾长，并测试纯扬声器播放不自触发、真实用户讲话可打断、旧音频不复播、近远场与不同噪声下的误触发/漏触发。编译通过不能替代声学验收。

流式 ASR 不等于自动讲话起止；默认仍是长按说话、松开发送。新增本地 WakeNet 唤醒在空闲时只处理设备 PCM，检测成功后进入有界自动录音；有讲话后静音结束、5 秒无讲话超时、20 秒封顶。编译与运行开关均默认关闭，已处理忙时关闭、旧队列/半帧清理；还需误唤醒、时延和资源实测。更自然的语义结束判定及端到端实时语音模型不进入当前主线。

## 3. 存储与外部服务：有需求再扩展

### 3.1 SD 与未来桌面同步

当前 SD 已用于设备侧原文、上下文快照、记忆、任务与索引，不再只是服务器对话的备份，也不需要再规划从文本“首次升级到 JSONL”。具体文件职责见 [本地记录与恢复](DEVICE_CLOUD_VOICE.md#本地记录与恢复m1)。

仍有价值的后续工作：

- **日志容量与轮转**：[已接入] 当前卷 8 MiB，新轮开始前预留 128 KiB，最多封存四卷；不覆盖或自动删除未导出的原文，满后停止日志追加。索引/设备搜索只覆盖当前卷并明确封存卷未搜索；定向删除包含所有受管卷。
- **受限导出与备份**：[已接入] 电脑白名单复制、SHA-256 核对、清单及目录落盘；默认不改原卡，显式选项才清理已备份封存卷。目录导出包含全部受管卷。无线导出、定时备份或多设备同步仍是候选，不让 Agent 任意浏览 SD。
- **隐私与清除**：明确明文记录、备份副本、旧文本和删除范围；同步系统必须传播删除/版本变化，防止已删除记忆被旧备份恢复。
- **离线边界**：可排队本地任务事件、日志或同步请求；断网并不会自动获得离线 ASR/LLM/TTS。不能把“离线队列”宣传为已经能完成离线云端对话。

若将来确需桌面侧长期归档或重检索，优先考虑设备主动增量同步。需设计稳定记录标识、幂等去重、ACK/游标、批量上限、断线重试、认证和访问互斥。现有历史定位 ID 可能随原文重写失效，不能直接假设是永久跨设备同步 ID。

| 通道候选 | 何时有价值 | 主要边界 |
| --- | --- | --- |
| 设备主动增量上传 | 明确需要备份、桌面检索或多设备交换时，优先评估 | 不要求固定设备 IP；桌面离线不能拖住实时语音 |
| 受限 HTTP 读取 | 同网诊断或导出明确文件 | 设备发现、认证、分块、路径白名单和 SD 并发 |
| 双向 WebSocket | 同时需要资源更新、日志、控制和持续双向事件时 | 请求 ID、ACK、超时取消、重连及迟到数据复杂度更高 |
| USB MSC | 人工维护或导出 | 必须避免电脑和 ESP32 同时读写同一文件系统，不作为在线 Agent 主通道 |

这些通道均非当前主线。新增桌面数据库前，先确定哪些数据由设备维护、哪些由桌面派生；不要预设 SQLite 已是当前事实源，也不要形成两个互相覆盖的上下文中心。

### 3.2 搜索、日历与更丰富的数据源

当前天气已有专用缓存工具，不是尚未实现的通用搜索。只有用户明确需要新闻、资料或其他实时信息时，再考虑选择性 Web Search。

搜索工具要有来源/时间、长度与次数上限、超时、失败降级及注入防护；不需要实时信息的请求不额外联网搜索。引入外部编排服务时维持现有设备直连可用，不能为了搜索强制整条语音迁回电脑。

日历、跨设备任务、环境传感器和更丰富 UI 的收益与依赖见下一节。摄像头、通用远程文件管理、无限外设联动、复杂多 Agent 和整体模型迁移暂不进入当前关键路径；出现明确场景后再重新评估，而不是保留无期限的完整实施清单。

## 4. 主页面、桌面功能与小游戏实施范围（2026-10-03）

### 4.1 范围与当前基线

定位是“常驻信息主页面 + 语音/提醒反馈 + 必需的本地短时娱乐”。九款游戏放在一个工具入口，不加入日常翻页循环。任务、专注、游戏和设置已接入，保留时钟/天气/语音页面、既有屏幕方向及现有硬件，不把信息塞进一屏。

状态约定：**[已接入]** 表示代码已有能力；**[已有反馈]** 表示已有使用反馈但不覆盖所有边界；**[待验收]** 表示仍需最新固件实机验证；**[新增建议]** 表示本次规划，不得写成已完成。未标为现状的设计、验收目标和优先级均为新增建议。

| 领域 | 核对后的现状 | 本轮真正新增的方向 |
| --- | --- | --- |
| 页面 | [已接入] 时钟、天气、语音、桌面工具四页；首页增加计时/下一提醒/待办摘要 | 长标题与棱镜有效视区待实测，不自动闲置回首页 |
| 天气 | [已接入] Open-Meteo 当前天气，默认杭州；详情和首页显示过期状态 | 位置设置入口和预报尚未新增 |
| 提醒/待办 | [已接入] 最多八条记录，ID 列表/详情/确认，语音编辑，稍后/完成/取消/删除及三种循环规则 | 首次日期、同名任务和 SD 失败待实测；不含任意日历 |
| 到期播报 | [已有反馈] 单次提醒到期；[已接入/待验收] 云端事项播报与固定本地离线语音，无前置滴声 | 本地音源只承诺按键取消；有效时间和物理出声需验证 |
| 输入 | [已接入] 基础页切页/语音、工具选择/确认、游戏动作/暂停及连续双轴倾斜 | 同一事件不同时触发游戏与页面；失去传感器样本暂停 |
| 硬件/显示 | [文件事实] ESP32-S3、240×240 ST7789、LVGL 9、MPU6050/6500 兼容驱动、microSD、麦克风和扬声器 | 不以增购触摸屏、方向键或手柄为首版前提；不假定已具备室内温湿度或电量测量 |
| 小游戏 | [已接入/待验收] 叠塔、跑酷、双车道、接落物、迷宫、飞行、打砖块、Pong、反应测试 | 本地规则与固定图形，无音效/云调用；未测实机帧率 |
| 专注与设置 | [已接入/待验收] 倒计时/番茄钟、NVS 恢复与最高纪录、0～100% 音量、唤醒开关、存储状态 | 重启计时保持暂停，阶段结束手动继续 |

当前语音与天气由设备直接访问云服务，不要求电脑 FastAPI 常驻；旧服务器 SQLite 方案不是当前在线上下文中心。提醒到期不调用 LLM，但目前仍依赖云端 TTS 发声，不能据此称为离线闹钟。

### 4.2 主页面可展示什么：按信息价值分层

推荐首页只承担三个问题：“现在几点”“环境/网络怎样”“接下来有什么事”。更丰富不等于更多小字；任务详情、天气详情和游戏放在独立页面。

| 内容 | 数据来源 | 展示方式与收益 | 离线/失败行为 | 优先级与依赖 |
| --- | --- | --- | --- | --- |
| 时间、日期、星期 | 本机时钟，联网通过 SNTP 校时 | 保留大时间；日期与星期用一行 | 本次启动已校时且持续供电时可继续走时；冷启动未校时明确标记不可用，不能假定断电后仍准确 | P1：整理已有信息；依赖时钟有效性 |
| 当前天气/室外气温 | 当前 Open-Meteo 缓存 | 首页一行摘要，详情页保留城市/体感/更新时间 | 保留已有缓存并标注过期；无缓存显示“暂无数据”，不伪造实时值 | P1：完善现有天气显示 |
| 下一次提醒 | 本机已保存的任务与到期时间 | 首页底部时间 + 标题，语音创建结果可见 | [已接入] 列表本地读取；断网固定语音播报，具体内容看屏幕 | 验收时间/显示/播报一致 |
| 待办概览 | 本机任务状态 | 首页仅显示未完成数量或一项；独立页查看其余任务 | 已加载的任务可显示；存储失败与状态未知不得显示“已完成” | P1：复用现有任务，不建立第二套清单 |
| 倒计时/番茄钟 | 设备单调计时与 NVS 快照 | [已接入] 专注页与首页剩余时间；阶段完成通知 | 断网计时；重启恢复最后保存值并暂停；本地语音通知 | 验收暂停、阶段与重启行为 |
| 室内温湿度 | 待采购并接入的环境传感器 | 可与室外天气区分显示，增加桌面实用性 | 读数失败标记无效，不把历史值当实时值 | P3：先确认需求、接口与安装位置 |
| 日历/下一场会议 | 用户选择的日历服务/API | 只显示下一事项，完整日程放详情页 | 显示缓存时间；登录过期、同步失败有明确提示 | P3：需要账号授权、同步和隐私策略 |
| 像素宠物/主题动画 | 本地图形/资源，少量状态 | 空闲陪伴感、与语音状态呼应 | 可离线运行，资源失败退回默认界面 | P3：先做轻动画，不承诺复杂养成 |
| Wi-Fi、异常；静音（若实现） | 本机真实状态 | 小图标；仅重要异常显示短文字 | 真实反映断网/失败，不能把 Wi-Fi 已连接等同于云服务可用 | P1：先优化可理解性 |

温度必须标注来源：现有天气气温不是房间温度；不使用 MPU 内部温度冒充室温。天气位置当前有默认配置，不是尚未选定供应商；需用户决定是否沿用杭州/Open-Meteo、是否增加位置设置。室内传感器型号应在采购前另行评估。没有电池与电量采样依据时不添加虚假的电量图标。

### 4.3 240×240 信息架构与交互

建议首页从上到下分为：小状态区 → 大时间 → 日期 → 天气摘要 → 下一事项。空间不够时让底部“下一事项”替换次要内容，不靠缩小所有字体硬塞。没有任务时显示简短空状态或保持留白，不自动制造待办。

页面职责建议：

1. **主页面**：常驻、快速扫读，不展示长回答或完整待办列表。
2. **天气页**：复用现有页面；再加过期提示、必要时扩展预报，不重复堆多个天气首页。
3. **任务页**：显示下一提醒、少量待办与状态；更多内容逐项翻看，长标题不挤成小字。
4. **专注页（已接入）**：倒计时/番茄钟、暂停、结束；不与时钟页面混为一体。
5. **娱乐入口（已接入）**：进入游戏后独占内容区；九款游戏都从一个入口选择。

本轮采用“原三页 + 一个桌面工具页”，任务、专注、游戏和设置都从工具页进入。基础页仍短按翻页/长按说话；工具内短按选择/长按确认，游戏长按暂停后从菜单发起语音，避免单键的确认/录音冲突。不假定触摸或额外按键。

语音、提醒与游戏需要共用明确的界面和音频占用规则：

- 普通语音结束后按既有返回策略恢复页面，不强制改变用户主动选择的天气/任务页；是否闲置后自动回首页由用户决定。
- 游戏中发起语音或处理到期提醒时暂停游戏、停止游戏音效，底层不得继续计时导致用户无故失败。
- 提醒与语音冲突先沿用当前“忙时等待空闲”的规则，不因新增 UI 擅自改成强制打断。后续若要抢占，需要用户选择并单独验证。
- 返回游戏显示暂停状态，用户确认后继续。音频只能有一个明确拥有者，不能混播提醒、TTS 和游戏音效。
- 长标题、生僻字、错误文字要测试当前字体子集；避免只设计正常短文本。

### 4.4 闹钟、提醒、待办与专注的增强顺序

提醒支持 60 秒～30 天相对时间、有限日期/钟点及每天/周一至周五/每周循环，不支持任意账号日历或节假日表。到期且语音空闲时提交，晚到超过五分钟记录错过并推进下次周期；断网使用固定本地语音，不反复重播旧周期。循环锚点、结果与下次日期持久化，最新代码需实机验收，具体以实施方案 M7 为准。

推荐增强顺序：

1. **先可见**：语音保存成功后显示标题和到期时间；首页显示下一项；列表区分待执行、已提交、错过、失败。提交过播报不等于用户已听到或已完成事项。
2. **再可管理**：提供精确选中的任务编辑/取消/删除与“稍后提醒”。使用稳定任务标识，重复标题不应误删；写入成功才显示成功，失败保留原状态。当前的待办完成逻辑不等于这些管理能力已实现。
3. **再可靠降级**：增加本地短提示音和屏幕通知作为断网备选；明确静音、勿扰、错过处理。与语音共用音频占用规则，不在 UI 刷新中同步请求 TTS。
4. **循环规则**：[已接入] 每天/工作日/每周、锚点计算与正常重启去重；稍后只推迟本次，编辑时间/循环规则更新锚点，工作日首次跳过周末。
5. **专注体验**：[已接入] 单调时钟倒计时与番茄钟，不每秒调用模型；重启恢复最后保存值并暂停，用户明确继续。

离线闹钟不是显示一张卡就完成。需验证有效时钟、任务恢复、离线音源和声音占用；断电后没有可用时间依据时不得承诺准时提醒。首版不为这些功能增加云端日历或全新任务数据库。

### 4.5 小游戏范围与输入取舍

以下九款可行游戏已经作为本轮必需范围实现规则、输入与暂停菜单；没有在当前硬件上测得帧率或内存结论。打砖块/Pong 分成两款，2048/贪吃蛇/俄罗斯方块仍受现有单键输入限制而暂缓，不用增加硬件或强塞多击操作扩张范围。

| 游戏 | 本轮操作与画面 | 收益/匹配度 | 相对难度 | 实机关注点 |
| --- | --- | --- | --- | --- |
| 一键叠塔 | 短按停止横移方块，切去未对齐部分；彩色方块与层数 | 很高；设备可静放桌面 | 低～中 | 时机判定与按键延迟 |
| 跑酷 | 自动前进，短按跳跃；不加蹲下或二段跳 | 很高；规则直观 | 中 | 方屏视野、障碍间距与碰撞宽容度 |
| 双车道躲避 | 自动前进，短按左右换道 | 高；无需新硬件 | 低～中 | 障碍可躲避，避免随机必死局 |
| 倾斜接落物 | 左右小幅倾斜控制篮子 | 条件性高；展示已有 IMU 的价值 | 中 | 需要连续轴输入、校准与死区；先确认握持与棱镜视角 |
| 倾斜迷宫 | 双轴倾斜控制方块，到达绿色出口 | 有特色；展示传感器交互 | 中～高 | 外壳/供电线/视角限制，两轴方向与墙面碰撞 |

| 打砖块/Pong | 两款独立游戏；短按切换底部挡板移动方向，Pong 含顶端 AI | 可行；规则经典 | 中 | 单键换向手感、反弹与漏接逻辑 |

| 2048/贪吃蛇/俄罗斯方块 | 通常需要四方向或多个动作 | 方屏显示合适，但当前输入不匹配 | 中～高 | 暂缓；不为一款游戏先改硬件或强塞多击操作 |

不再保留“只做一款”的限制。九款共用一个纯 C 规则模块和固定 LVGL 图形池；打砖块/Pong 用单键反向挡板，接落物/迷宫使用连续倾斜。是否舒适、稳定仍需实机操作，规则实现不等于棱镜与外壳已适合长时间游玩。

像素宠物可以作为独立的后续视觉主题，不等于上述游戏；初版只做表情和空闲动作，不让喂养、情绪或奖励系统挤占实用功能。

### 4.7 小游戏的嵌入式适配与验收门槛

- **输入模式**：菜单、游戏、语音忙状态分别处理输入。同一次短按不能既跳跃又翻页；倾斜游戏不能同时触发页面切换。需明确进入/退出/暂停方式，以及长按说话是否全局保留。首版避开持续按住控制的游戏，以减少冲突。
- **按钮响应**：复用独立采样任务，但在实现前决定动作在稳定按下还是松开时触发，并测量消抖与调度延迟；长按进入语音前是否会先触发一次游戏动作也需明确定义。
- **倾斜输入**：已有50Hz采样和阈值翻页可提供基础，但400ms翻页冷却不能直接当游戏控制。接落物需连续单轴，迷宫需双轴；新增限速、死区、滤波、方向标定和传感器失效暂停。
- **显示**：优先大块图形、高对比度、少文字；使用现有统一旋转/镜像配置，不再次翻转。根据棱镜有效视区实测边缘可见性，横屏OLED示例不能直接拉伸。稳定20～30 FPS仅为初始调试目标，不是已测性能。
- **资源**：固定上限的游戏对象和缓冲，避免逐帧分配、SD读写及无限动画。页面不可见时停止游戏更新；音频任务和提醒优先，网络/文件操作不得长时间占用显示锁。
- **音频**：首版可无音效。后续提示音须本地播放并服从统一音频占用，语音或提醒开始时立即停止游戏声音，不并发争抢I2S。
- **存储**：最高纪录只在变化后有限写入；少量记录可考虑NVS，贴图等资源按需放SD。不逐帧写分数，也不把游戏数据混进对话记忆。缺卡、资源损坏时回退默认资源或明确不可用。
- **容量与测试**：先核实实物模组Flash/PSRAM型号，再测空闲堆、最低堆、任务栈与帧耗时；配置文件中的容量不等于实物已确认。

首款游戏验收至少覆盖：反复进入/退出、长时间游玩、语音中断后返回、提醒到期、网络断开、缺卡/资源失败、按键长短按边界，以及连续暂停恢复后无旧音效/计时跳变。倾斜游戏另测静止漂移、传感器失败、握持舒适性与外壳稳定性。测试失败时先修共存问题，不靠提高帧率或增加游戏数量掩盖问题。

无线同步、语义检索和多用户档案需要新的服务与身份设计；账号日历、新传感器、电池采样、像素宠物需要账号/硬件/素材，不在本轮固件中伪造数据。没有这些依赖时，保留现有可运行路径。

### 4.9 已采用的选择与仍需外部条件的事项

已采用：保留时钟和天气并加入下一事项；不强制闲置回首页；九款游戏从统一入口进入；工具内长按确认、游戏长按暂停，语音走菜单；提醒忙时等待空闲而不强制打断；计时阶段手动继续，断电恢复暂停；默认专注 25/5、音量 35%，设备设置可调整。

仍需外部条件：更换天气城市/预报源、账号日历授权、室内传感器型号与接线、电量采样、桌面同步目标/权限、像素宠物素材，以及棱镜/供电线下倾斜游戏的实际握持反馈。当前不主动采购、改板、部署服务器或调用新增账号服务。
